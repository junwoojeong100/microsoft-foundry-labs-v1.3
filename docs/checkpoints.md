# 막히지 않고 진행하는 방법

[English](en/checkpoints.md) | **한국어** · [전체 과정](../README.ko.md)

한 번에 한 단계만 진행합니다. **명령 입력 → 결과 확인 → 다음** 순서를 유지하세요.

별도 작성·제출 단계는 없습니다. 명령이 저장한 설정과 결과 파일을 그대로 보관합니다.

> [!TIP]
> 처음에는 **한 언어의 기본 경로만** 따라갑니다. 과거 검증 보고서와 접힌 복구 절은 추가 과제가 아닙니다. 장을 건너뛰었다면 다음 장의 **시작 조건**부터 확인하세요.

## 명령과 자리표시자 읽기

| 문서에 보이는 것 | 할 일 |
|---|---|
| `python ...`, `az ...`, `azd ...` | README가 있는 폴더의 터미널에서 한 줄씩 실행합니다. |
| `bash` / `powershell` | 코드 상자의 언어 표시입니다. 이 단어 자체는 입력하지 않습니다. Python 명령은 활성화된 가상 환경에서 두 셸 모두 사용합니다. |
| `실제-...`, `YOUR-...`, `ACTUAL-...`, `<...>` | 바로 앞 단계에서 확인한 **내 값**으로 바꿉니다. 따옴표는 남기고 꺾쇠는 넣지 않습니다. |
| `--label baseline` | 결과 묶음 이름입니다. 첫 실행은 예시 이름을 써도 됩니다. 바꾸면 후속 `evaluate`·`compare` 등의 참조도 모두 바꿉니다. |
| `--output outputs/...json` | 답변을 저장할 새 파일 경로입니다. 실행 뒤 편집기에서 그 파일을 엽니다. |
| JSON/YAML/질문만 있는 상자 | 터미널 명령이 아닙니다. 안내한 파일에 저장하거나 Playground의 질문 입력란에 붙여 넣습니다. |
| `선택`, `대신`, 접힌 복구 절 | 기본 명령에 **추가로 전부 실행하지 않습니다**. 해당 조건일 때만 실행합니다. |

### 명령 하나를 실행하는 순서

1. **상자 위 설명을 읽습니다.** 실행 위치와 바꿀 값을 확인합니다.
2. **상자 하나를 복사·실행합니다.** 각 실행 상자에는 명령 하나만 있습니다.
3. **프롬프트가 돌아오면 결과를 확인합니다.** 바로 아래의 확인 안내와 맞아야 다음 상자로 갑니다.

`serve`처럼 실행한 채 두는 서버만 예외입니다. 그 장의 [터미널 A/B 안내](#두-터미널을-사용하는-장)를 따릅니다.

> [!TIP]
> 긴 명령은 가로로 스크롤하거나 복사 버튼으로 **한 줄 전체**를 복사합니다. 화면의 자동 줄바꿈은 괜찮지만, 직접 Enter·`\`·PowerShell 백틱을 넣지 않습니다. 질문·경로·옵션은 같은 명령에 속해야 합니다.

JSON·YAML·질문·출력 예시는 여러 줄일 수 있습니다. 이 상자는 터미널에 실행하지 않고, 바로 앞에서 안내한 편집기·Playground·결과 확인 위치에서 사용합니다.

> [!WARNING]
> `--confirm-create`, `--confirm-cost`, `--confirm-delete`는 각각 생성·과금·삭제 의사를 명시합니다. **이 옵션이 없는 모델 호출도 과금될 수 있습니다.** 실행 전에 호출 대상과 비용을 확인하세요.

## 결과 파일을 읽고 다음 명령에 값 옮기기

편집기의 파일 탐색기에서 출력된 경로를 엽니다. 폴더만 만들어졌거나 마지막 줄에 경로가 표시됐다는 이유로 성공으로 판단하지 않습니다.

| 출력/파일 | 읽는 방법 |
|---|---|
| `.json` | `"이름": 값` 형식입니다. 다음 명령에는 **필드 이름이 아닌 값만** 복사합니다. |
| `.jsonl` | 한 줄이 사례 하나입니다. 6문항 결과라면 실제 6행과 각 행의 오류를 확인합니다. JSON 배열로 바꾸지 않습니다. |
| `.html` | 편집기에서 코드만 읽지 말고 파일을 브라우저로 열어 표와 사례별 결과를 봅니다. |
| `true` / `false` / `null` | 참 / 거짓 / 값 없음입니다. `null` 사용량은 0원이나 호출 없음이 아닙니다. |
| `manifest.json` | 이번 실행의 모델·지침·데이터·설정을 기록합니다. 답변은 해당 응답 파일에서 확인합니다. |
| `result_directory` 또는 저장 경로 | 그 폴더/파일을 엽니다. 응답·평가·소유권 파일은 각각 다른 기록입니다. |

### 이름과 경로를 옮길 때

같은 `--name` 옵션이라도 받는 값이 다릅니다.

- **`prepare-hosted --name hosted`:** `hosted`는 접두사 뒤의 짧은 이름입니다. 이후 `azd deploy`에는 도구가 출력한 **전체 서비스 이름**을 넣습니다.
- **`prompt-agent create --name`:** 내 접두사를 포함한 **전체 agent 이름**을 받습니다.

08장 이후의 패키지 경로·준비 폴더·서비스·버전은 [08의 값 복사 표](08-hosted.md#3-기존-프로젝트에-연결하는-독립-폴더)를 보고 **실제 출력값**을 다음 명령에 복사합니다.

`--cwd`는 azd 한 명령의 대상 폴더만 지정합니다. 터미널의 현재 위치를 바꾸는 옵션이 아니므로, 터미널은 계속 README가 있는 폴더에 둡니다.

## 다음 날 재개하기

> [!IMPORTANT]
> 같은 프로젝트라면 **설치·생성부터 다시 하지 않습니다.** 이전 폴더 전체와 `.env`, `.selfstudy/`, `outputs/`를 유지합니다.

### 1. 기존 실습 폴더 열기

편집기에서 기존 실습 폴더를 열고 새 터미널을 엽니다.

### 2. 내 OS의 가상 환경 활성화

다음 두 상자 중 **본인 OS의 명령 하나만** 실행합니다.

**macOS / Linux**

```bash
source .venv/bin/activate
```

**Windows PowerShell**

```powershell
.\.venv\Scripts\Activate.ps1
```

활성화가 조직 정책으로 막히면 정책을 바꾸지 말고 `python` 대신 `.\.venv\Scripts\python.exe`를 사용합니다.

### 3. 로컬 준비와 저장한 설정 확인

이어서 모든 OS에서 실행합니다. 00장의 `configure`를 마친 환경이어야 합니다.

**로컬 준비 확인**

```bash
python scripts/workshop.py doctor
```

**로컬 준비 결과를 확인한 뒤 저장한 설정 읽기**

```bash
python scripts/selfstudy.py values
```

| 확인 결과 | 다음 행동 |
|---|---|
| `PASS`와 내 프로젝트·접두사·모델이 맞음 | 저장한 결과를 확인하고 이어갑니다. |
| `먼저 Lab 00의 configure` | [00의 설정 단계](00-setup.md#8-실제-값으로-설정-자동-수집)로 돌아갑니다. |
| 로그인 만료 | 00의 정상 `az login` / `azd auth login` 절차를 따릅니다. |

`values`와 `status`는 **저장된 설정을 읽는 명령**입니다. Azure 자원의 현재 존재나 상태를 검사하지 않습니다.

### 4. 저장한 결과에서 이어가기

[저장 위치 표](#설정과-결과를-다시-찾는-곳)에서 해당 장의 결과를 열고 **완료 확인**과 대조합니다. 아직 수행하지 않은 다음 단계부터 이어갑니다.

이미 받은 답변을 확인하려면 파일만 열면 됩니다. 모델을 다시 호출할 필요가 없습니다.

### 두 터미널을 사용하는 장

05·08·10장에서는 두 터미널의 역할을 구분합니다.

| 터미널 | 할 일 | 정상 상태 |
|---|---|---|
| A | 서버 실행 | 프롬프트 대신 로그가 계속 표시됨 |
| B | 상태 확인·요청 전송 | 명령 결과를 확인하고 다음 요청 실행 |

편집기의 새 터미널 버튼으로 B를 엽니다. A와 같은 실습 폴더인지 확인하고 **B에서도 `.venv`를 활성화**합니다.

끝나면 **A에서** `Ctrl+C`로 내 서버를 중지합니다.

## 같은 이름으로 다시 실행해도 되나요?

| 상황 | 다음 행동 |
|---|---|
| 응답/label/패키지/준비 폴더가 이미 있음 | 먼저 기존 결과를 읽습니다. **새 실행이 필요한 경우만** `candidate-2`, 새 `--output`, 새 `--run` 등을 선택하고 후속 참조도 맞춥니다. |
| File Search 인덱싱 또는 관리형 red-team job이 아직 진행 중 | 해당 장의 **같은 ID/label로 상태 조회·재개** 절차를 사용합니다. 새 자원을 중복 생성하지 않습니다. |
| 설정·원문·코드·모델을 바꿔 비교하고 싶음 | 이전 결과를 보존하고 변경 조건을 기록합니다. 지침만 비교하려면 같은 코드·데이터의 새 baseline/candidate 쌍이 필요합니다. |
| 비용·권한·기능 지원이 막힘 | 생성 반복, 모델 대체, 권한 확대부터 하지 않습니다. 원래 오류와 남은 자원을 기록합니다. |

## 매 장에서 확인할 네 가지

- 내가 만들거나 바꾸는 대상이 무엇인가?
- 지금 사용하는 프로젝트·모델·버전이 맞는가?
- 실제로 확인한 결과는 무엇인가?
- 멈춘다면 무엇을 정리해야 하는가?

명령의 종료, 실제 응답, 품질 통과는 서로 다릅니다. 실패나 미지원 기능은 그대로 기록하고 [문제 해결](troubleshooting.md)의 해당 항목부터 확인합니다.

### 오류가 보이면 다음으로 가도 되나요?

| 실제 상태 | 다음 행동 |
|---|---|
| `ERROR`, traceback, 인증/API 오류, 응답 누락 | 의존하는 다음 명령은 멈추고 해당 장과 문제 해결을 확인합니다. 파일이 생겼어도 성공이 아닙니다. |
| 07의 응답 6개·요청 오류 0개, 일부 업무 검사 실패 | 실패를 읽고 지침 비교는 계속할 수 있습니다. 낮은 점수를 지우려고 같은 수집을 반복하지 않습니다. |
| 관리형 job이 아직 실행 중인데 로컬 대기만 timeout | 해당 장의 같은 ID/label 조회·재개 안내를 사용합니다. 새 job을 제출하지 않습니다. |
| 품질 기준 실패 또는 관리형 판정 불일치 | 분석 결과를 보관하고 최종 인수·holdout은 보류합니다. [15의 중지·정리](15-capstone-cleanup.md#4-먼저-실행-중인-것을-멈추기)는 그대로 수행합니다. |

| 01~02 | 실제 Sol 응답과 결과 JSON 확인. 지침/지식의 차이를 설명. Luna·Router는 실행 또는 선택적 미실행으로 기록 |
| 03 | 파일 6개 인덱싱, 실제 File Search 호출, 내 파일 인용을 확인 |
| 04~05 | 함수/MCP의 실제 실행과 반환값을 확인. 모의 승인과 실제 인가는 구분 |
| 06 | keyword·IQ·Hybrid·IQ Chat 각각의 실제 근거 확인. **원래 index로 복귀**한 설정 보관 |
| 07 | dev 6행·오류·업무 검사, policy 3개 기준과 calibration의 실제 판정 확인. 실패 분석은 가능하지만 최종 인수는 아님 |
| 08 | 패키지 → 로컬 응답 → 정확한 원격 버전의 응답을 각각 확인 |
| 09 | 연결 뒤의 새 응답을 실제 trace에서 확인. 예약 평가는 중지 |
| 10 | Toolbox 목록뿐 아니라 조회·답변·Skill load 확인. Skill과 Toolbox 버전은 따로 기록 |
| 11 | Memory alpha/beta·A2A 실제 위임·예약의 원래 응답 확인. Routine은 disabled |

포털이 열리거나 CLI가 종료됐다는 사실만으로 다음 단계의 자산이 준비되었다고 가정하지 않습니다.

## 막힌 단계가 있을 때

먼저 **막힌 기능에 의존하는 단계만** 멈춥니다.

- **Search가 없을 때:** 06의 Search 의존 단계와 10의 Toolbox/OpenAPI는 멈춥니다. 07의 `local` 검색 평가는 진행할 수 있습니다.
- **12에서 로컬 검색을 선택했을 때:** Search/IQ 실습 성공으로 기록하지 않습니다.
- **Hosted를 사용할 수 없을 때:** 08/12의 원격 실행을 미실행으로 남기고, 15의 SDK 대상과 구분합니다.

| 막힌 지점 | 가능한 다음 행동 |
|---|---|
| 00~01의 기본 Sol 배포·첫 호출 | 다른 모델로 대신하지 않고 Azure 실습을 멈춥니다. 이미 만든 자원은 15에서 확인합니다. |
| 03 File Search 또는 04 Code Interpreter만 미지원 | 해당 도구를 미실행으로 기록합니다. 기본 모델이 동작하면 04의 로컬 MAF·함수/MCP, 05로 진행할 수 있습니다. |
| 06 Hybrid 또는 IQ Chat만 미지원 | keyword/IQ 결과는 따로 보관합니다. 07은 local, 10은 원래 keyword index를 사용하며 Hybrid/IQ Chat 성공을 요구하지 않습니다. |
| 08 원격 Hosted 배포만 미지원 | 로컬 준비가 가능하면 1~3절의 폴더는 연결용으로 쓸 수 있습니다. 09의 Prompt Agent trace, 10의 비-Hosted 도구, 11의 준비된 기능만 진행합니다. |
| 11의 Memory 또는 embedding만 미지원 | Memory는 미실행으로 남깁니다. A2A는 08의 준비 폴더, Routine은 03의 Prompt Agent와 09의 로그가 있으면 각각 진행할 수 있습니다. |
| 12 Optimizer 미지원 또는 후보 0개 | 상태를 기록한 뒤, 선행 조건이 준비된 Hosted `v1`/`v2` 비교로 갑니다. 후보가 없다는 이유로 원문·기준을 바꾸지 않습니다. |
| 13 Hosted 정책 실험 미지원 | 2~4절을 미실행으로 남깁니다. 별도 Prompt Agent·judge·로그 조건을 갖췄다면 5절 관리형 검증은 따로 확인합니다. |
| 14 GitHub 권한 없음 | 15로 갑니다. 14를 건너뛰는 것이 다른 품질 기준을 면제하지는 않습니다. |

다른 프로젝트로 전환할 때는 [00의 보관/새 workspace 절차](00-setup.md#새-프로젝트에서-이전-상태를-인수하지-않기)를 따릅니다. 보관한 이전 CI ID나 배포 이름만으로 새 프로젝트의 권한·자산 소유권을 가정하지 않습니다.

실패 출력은 보관하고, 미지원·미실행을 완료로 판단하지 않습니다. [검증 보고서](validation-report.md)의 성공/실패는 본인의 실행을 대신하지 않습니다.

> [!WARNING]
> 중단 시에는 [15의 중지 단계](15-capstone-cleanup.md#4-먼저-실행-중인-것을-멈추기)로 이동합니다. **Search Basic은 요청하지 않아도, 보존한 저장소는 compute를 멈춰도 비용이 남을 수 있습니다.**

## 파일 전달

개인 설정 없이 실습 자료를 압축하려면:

```bash
python scripts/package_workshop.py
```

ZIP에는 코드·데이터·가이드·테스트가 함께 들어갑니다. `.env`, `.selfstudy`, 실행 결과와 가상 환경은 제외됩니다. 받은 사람은 압축을 풀고 [00](00-setup.md)부터 시작합니다.

이미 ZIP이 있다면 덮어쓰지 않습니다. 새 배포본이 필요할 때만 `--output dist/workshop-new.zip`처럼 아직 없는 파일명을 지정하고 생성된 manifest를 확인합니다.
