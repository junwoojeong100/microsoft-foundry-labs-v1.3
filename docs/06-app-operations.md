# Lab 06. 앱과 Foundry 운영 화면

**55분 · 로컬 브라우저 앱·Foundry 포털 · 목표: 같은 에이전트를 앱에서 쓰고, 포털에서 평가·추적합니다.**

| 시간 | 할 일 |
|---|---|
| 15분 | 로컬 앱으로 실제 질문 |
| 10분 | 기존 응답의 Foundry 평가 제출 |
| 15분 | 실제 trace 확인 |
| 10분 | 사용량·비용·권한 확인 |
| 5분 | 평가 결과와 운영 기록 저장 |

## 1. 에이전트를 앱에 연결하기

선택 버전을 먼저 확인합니다.

```bash
python lab.py status
python -m streamlit run app.py --server.address 127.0.0.1 --browser.gatherUsageStats false
```

표시된 로컬 주소를 엽니다. 기본값은 `http://127.0.0.1:8501`입니다. 이 터미널은 서버 실행 중인 상태로 둡니다.

앱 화면에는 **실습용 도우미, 에이전트 이름, 버전**이 표시됩니다. 다음 질문을 전송합니다.

```text
2026년 9월 서울 2박 3일 출장의 숙박비와 식비 상한을 계산해 주세요.
```

앱에서 확인합니다.

- 지원 상한 390,000원과 실제 파일 인용.
- **실제로 실행한 계산 도구** 영역의 인수와 반환값.
- **Response ID와 사용량** 영역.
- 승인·예약·결제를 수행하지 않는다는 안내.

앱은 [app.py](../app.py)의 화면과 앞에서 쓰던 `ask` 함수를 연결한 것입니다. **UI를 바꿨다고 모델·도구 로직을 다시 만들지 않았습니다.**

각 질문은 독립 요청입니다. “그럼 부산은?” 대신 날짜·도시·기간을 모두 적습니다. 이 앱에는 대화 메모리나 사용자 인증을 추가하지 않았습니다.

**같은 실습 폴더에서 앱과 CLI로 동시에 요청하거나 여러 사람이 함께 사용하지 않습니다.** 상태 파일은 개인 실습용입니다. 인터넷에 공개하거나 다른 사람에게 localhost 대신 네트워크 주소를 공유하지 않습니다.

## 2. Foundry 포털에서 실제 응답 평가

이번에는 평가 대상 에이전트를 다시 실행하지 않습니다. **Lab 05에서 이미 생성한 응답 데이터**를 평가합니다.

이유: 계산 함수는 로컬 Python에 있습니다. 포털의 Agent 평가를 선택해도 이 PC의 함수를 자동으로 실행할 수 없습니다. **Dataset 평가**는 이 차이를 피하면서 같은 실제 응답을 평가합니다.

1. Foundry의 **Evaluation → Create**를 엽니다.
2. Target은 **Dataset**, Scope는 **Individual turns**를 선택합니다.
3. 선택한 버전의 결과 폴더에서 **`foundry-evaluation.jsonl`**을 데이터로 업로드합니다. 기본 예: `outputs/improved/foundry-evaluation.jsonl`.
4. 데이터 미리보기에서 실제 질문 6개와 답변이 있는지 확인합니다. baseline 버전을 선택했다면 baseline 결과 파일을 사용합니다.
5. 필드 매핑을 확인합니다.

| 평가 필드 | 파일의 열 |
|---|---|
| query | query |
| response | response |
| ground_truth | ground_truth |

6. 담당자가 준비한 Azure OpenAI 연결과 judge 모델을 선택합니다.
7. 자동 선택된 다른 평가 항목은 해제하고 **Relevance 하나**만 선택합니다.
8. 평가 이름을 본인 실습 ID와 버전을 알아볼 수 있게 정합니다. 예: `trip-01-improved-relevance`.
9. 행 수, 모델, 필드 매핑, 평가 항목과 예상 과금을 확인한 뒤 **Submit**합니다.
10. 진행 상태와 평가 이름을 워크북에 적고, 실행 중에는 다음 trace 실습을 진행합니다.

Relevance는 **질문에 맞는 답변인가**를 보조적으로 판단합니다. 여기에는 실제 검색된 문맥을 `context` 열로 제공하지 않았으므로 **Groundedness를 선택하지 않습니다**. 파일 전체를 임의로 문맥에 넣고 “검색이 정확했다”는 점수로 해석하지도 않습니다.

**AI judge도 틀릴 수 있습니다.** 높은 관련성 점수를 출장 규정의 정확성, 올바른 도구 입력, 승인 통제의 증거로 대체하지 않습니다.

## 3. Foundry에서 trace 찾기

1. 앱의 **Response ID와 사용량**을 펼쳐 응답 ID를 복사합니다. 함수 결과 전후로 ID가 여러 개일 수 있습니다.
2. 같은 프로젝트의 **Agents → Traces**를 엽니다.
3. 시간 범위를 최근 1시간 등으로 맞추고, 에이전트 이름과 응답 ID로 찾습니다.
4. trace 한 건을 열어 시작 시각·상태·소요 시간과 세부 단계(span)를 봅니다.
5. 가능한 범위에서 모델 호출, File Search, 함수 호출 요청/결과를 확인합니다.

워크북에 **본인의 trace ID 또는 확인 가능한 상세 화면 정보**, 연결한 Response ID, 관찰한 단계 하나를 기록합니다.

```text
답변이 느리다
  → 모델 요청이 여러 번인가?
  → 검색에 시간이 걸렸나?
  → 함수 실행 전후의 요청이 이어졌나?
```

**로컬 JSON 실행 기록과 Foundry trace는 다른 것입니다.** JSON 파일이 생겼다고 포털 trace도 확인했다고 적지 않습니다. 또한 서버 측 trace만으로 내 Python 함수 내부의 모든 실행 시간이 보이지는 않습니다. 그런 분석에는 별도의 클라이언트 계측이 필요합니다.

trace가 없으면 몇 분 기다린 뒤 새로 고칩니다. 그래도 없으면 Application Insights 연결, 조회 권한, 시간 범위, 프로젝트를 확인합니다. 이전의 다른 사람 trace를 본인 결과로 쓰지 않습니다.

## 4. 비용과 권한을 눈으로 확인

한 번의 질문이 한 번의 모델 호출과 같지는 않습니다. 문서 검색과 함수 결과를 사용하면서 모델 호출이 이어질 수 있습니다.

| 항목 | 이 수업에서의 관찰/통제 |
|---|---|
| 모델 입력·출력 토큰 | 실행 기록 `responses[].usage`를 **모든 호출에 걸쳐 합산** |
| File Search | 검색·저장에 모델 토큰 외 과금 가능. 파일 3개만 사용 |
| judge 모델 | 포털 평가에서 추가 사용. 6행, Relevance 하나로 제한 |
| Application Insights | 로그 수집·보관 비용. 합성 데이터만 기록, 보관 정책 확인 |
| 과도한 반복 | 질문당 최대 함수 4회, 함수 결과 전달 최대 3라운드 |

사용량이 `null`이면 **미측정**이지 0이 아닙니다. 실패·재시도에서 추가 사용이 생길 수 있으므로 로컬 합산을 청구서의 정확한 금액으로 보지 않습니다.

토큰 비용의 기본 계산은 다음과 같습니다.

```text
입력 토큰 ÷ 가격표의 기준 토큰 수 × 입력 단가
+ 출력 토큰 ÷ 가격표의 기준 토큰 수 × 출력 단가
+ 검색·저장·judge·로그 등 별도 비용
```

단가는 [현재 Azure OpenAI 가격표](https://azure.microsoft.com/pricing/details/cognitive-services/openai-service/)와 계약·리전·배포 유형을 확인합니다. 캐시 토큰 등은 별도 단가가 있을 수 있습니다. **예산 알림은 자동 결제 차단 장치가 아닙니다.**

포털에서 현재 프로젝트와 연결 리소스를 다시 확인합니다. `.env`에는 API key가 없고, 로컬 프로그램은 CLI 로그인 사용자의 권한으로 실행됩니다. 운영 앱에는 사용자 인증, 서버 측 자격 증명 관리, 최소 권한 등을 별도로 설계해야 합니다.

## 5. 포털 평가 결과로 돌아오기

Evaluation 목록에서 제출한 평가를 엽니다.

- **Completed**인지 확인합니다. `Partial`이나 `Failed`를 완료로 기록하지 않습니다.
- 실제로 평가된 행 수와 누락/오류를 확인합니다.
- Relevance 원점수와 판정 설명을 한 행 읽습니다.
- Lab 05의 사람 평가와 비교해 **같은 점과 다른 점**을 적습니다.

화면의 점수 척도·임계값·judge 배포를 함께 기록합니다. 사전에 정한 점수가 반드시 나와야 하는 실습은 아닙니다.

**핵심 한 문장:** 업무용 AI는 답변 화면뿐 아니라 품질, 원인, 비용을 함께 볼 수 있어야 합니다.
