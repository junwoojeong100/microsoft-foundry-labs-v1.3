# 02. 모델·프롬프트·비교·Router

**완료 목표:** 지침과 지식의 차이를 경험하고, 모델 선택을 고정 조건으로 비교합니다.

**시작 조건:** 01의 모델 응답. 두 번째 모델과 Router는 본인이 이 장에서 추가할 수 있으며, 배포 가능 여부와 비용을 먼저 확인합니다.

## 1. 프롬프트만 바꿔 보기

Playground에서 같은 배포를 유지하고 **각 실험 전에 새 대화**를 엽니다.

첫 질문:

```text
부산 출장 준비를 도와줘.
```

두 번째 질문:

```text
당신은 신입 직원의 출장 준비 도우미입니다.
부산 출장 전에 확인할 것 3개를 정리하세요.
회사 규정, 날짜, 기간은 아직 제공하지 않았습니다.
비용이나 승인 여부를 추측하지 말고 필요한 정보를 되물으세요.
```

답변 길이, 가정한 정보, 확인 질문을 비교합니다. 역할·작업·제약·형식이 명확하면 행동을 더 일정하게 만들 수 있습니다.

## 2. 지침으로 만들 수 없는 지식

새 대화에서 묻습니다.

```text
한빛기술의 2026년 9월 국내 출장 숙박비 한도는 얼마인가요?
공식 근거도 알려 주세요.
```

모른다고 답하면 적절한 한계 인식입니다. 금액을 답하면 원문이 제공되었는지 확인합니다. 자신감이나 인용처럼 생긴 문자열만으로 정답이라고 판단하지 않습니다.

**프롬프트는 행동, 검색은 근거, 파인튜닝은 모델 가중치 변경**입니다. 이 과정의 지침 수정·문서 연결은 파인튜닝이 아닙니다.

## 3. 비교 모델을 직접 준비

두 번째 모델을 비교하려면 00의 모델 배포 절차를 반복합니다.

1. 같은 Foundry 리소스의 모델 카탈로그에서 다른 모델을 찾습니다. 예: `gpt-5-mini`.
2. Responses·Structured Outputs·지역·할당량을 확인합니다.
3. 기존 배포를 바꾸지 않고 `workshop-compare` 같은 **새 배포 이름**을 지정합니다.
4. 생성 완료와 실제 모델/버전을 기록합니다.
5. 비용이 부담되거나 지원되지 않으면 모델 비교는 미실행으로 기록하고 다음 장으로 갑니다. 같은 모델을 다른 이름으로 배포한 것을 성능 비교라고 하지 않습니다.

처음에는 한빛기술 규정도 함께 쓰는 직접 SDK 응답을 만들어 봅니다.

```bash
python scripts/workshop.py answer --prompt v2 --retrieval local --question "2026년 9월 국내 출장 숙박비 한도와 예약 전 절차는?" --output outputs/learner-notes-ko/02-model-a.json
python scripts/workshop.py --model-deployment workshop-compare answer --prompt v2 --retrieval local --question "2026년 9월 국내 출장 숙박비 한도와 예약 전 절차는?" --output outputs/learner-notes-ko/02-model-b.json
```

같은 지침·질문·로컬 근거를 사용합니다. `--model-deployment`는 **이 요청만** 바꾸며 `.env`나 Azure의 기본 배포를 변경하지 않습니다. 응답·근거·오류·사용량을 비교하되 한 질문으로 모델 순위를 확정하지 않습니다. 전체 dev 비교는 07에서 진행합니다.

## 4. Router를 직접 살펴보기

1. 카탈로그에서 **Model Router**를 찾습니다.
2. 제공되는 모델/모드, 지원 리전·API·배포 유형·가격을 읽습니다.
3. 실행하기로 결정했다면 본인 전용 배포를 만들고 **그 배포가 지원하는 Playground**에서 같은 질문을 보냅니다.
4. Router 버전과 실제 선택 모델이 노출되는지 확인합니다. 노출되지 않으면 “선택 모델 미확인”으로 기록합니다.
5. 직접 모델의 실패를 Router로 몰래 바꿔 성공 처리하지 않습니다.

Router는 고정 모델 하나가 아니라 **요청에 따라 모델을 선택하는 시스템**입니다. 특정 Router가 프로젝트 Responses API를 지원하는지 확인하기 전에는 같은 SDK 호출을 강제로 적용하지 않습니다. [공식 Router 평가](https://learn.microsoft.com/azure/foundry/openai/how-to/evaluate-model-router).
