# Lab 02. 모델과 프롬프트

**45분 · 브라우저와 터미널 · 목표: 지침으로 바꿀 수 있는 것과, 문서가 있어야 바뀌는 것을 구분합니다.**

| 시간 | 할 일 |
|---|---|
| 5분 | 모델 선택 기준 확인 |
| 15분 | 같은 모델로 두 프롬프트 비교 |
| 10분 | 사내 규정의 지식 한계 확인 |
| 10분 | 코드로 같은 배포 호출 |
| 5분 | 결과와 다음 가설 기록 |

## 1. 가장 큰 모델이 정답일까요?

우리 도우미에 필요한 것은 긴 창작 능력보다 **짧은 한국어 답변, 문서 활용, 도구 호출, 기다릴 만한 속도와 비용**입니다.

모델 상세에서 기반 모델, 지원 기능, 배포 유형을 확인합니다. 이 실습의 기본 후보 `gpt-4.1-mini`를 반드시 모든 업무의 최선이라고 결론 내리지 마세요. 모델 선택은 **같은 업무 질문으로 확인하는 실험**입니다.

이번 비교에서는 모델을 바꾸지 않습니다. **한 번에 지침 하나만 바꿔야 차이의 원인을 알 수 있습니다.**

## 2. 실험 A: 막연하게 부탁하기

Playground에서 이전 대화를 지웁니다. **New chat / Clear chat**을 사용해 앞 대화의 영향을 줄입니다.

```text
부산 출장 준비를 도와줘.
```

실제 답변을 워크북에 복사합니다. 다음 세 항목을 봅니다.

| 관찰할 것 | 메모 |
|---|---|
| 너무 긴가? | 필요한 정보가 바로 보이는가 |
| 무엇을 가정했는가? | 날짜, 기간, 회사 규정을 임의로 정했는가 |
| 다음 행동이 분명한가? | 무엇을 더 알려 주면 되는가 |

친절한 답변이면 성공입니다. 반드시 틀린 답변이 나와야 하는 실험이 아닙니다.

## 3. 실험 B: 역할·작업·한계·형식을 분명하게

다시 새 대화를 시작합니다. 같은 `workshop-chat` 배포를 유지합니다.

```text
당신은 신입 직원의 국내 출장 준비를 돕는 도우미입니다.

작업: 부산 출장을 준비할 때 먼저 확인해야 할 것을 정리하세요.
한계: 회사 규정과 날짜, 출장 기간은 아직 제공하지 않았습니다.
      비용이나 승인 여부를 추측하지 마세요.
형식: "먼저 확인할 것" 3개와 "제가 추가로 알려 드릴 것" 2개로 짧게 답하세요.
```

**기대 결과:** 답변 구조가 더 일정하고, 알 수 없는 내용을 확인 질문으로 돌립니다.

이것이 **프롬프트**입니다. 장식적인 문장을 길게 쓰는 것보다 “무엇을 하며, 무엇을 모르는지, 어떤 형식으로 답할지”를 구체화합니다.

## 4. 그런데 프롬프트만으로 회사 규정을 알 수 있나요?

새 대화에서 묻습니다.

```text
다온테크의 2026년 9월 서울 출장 숙박비 상한은 1박 얼마인가요?
공식 근거와 함께 답해 주세요.
```

나올 수 있는 결과는 두 가지입니다.

- 모른다고 답함: **올바른 한계 인식**입니다. 하지만 직원이 필요한 답은 아직 얻지 못했습니다.
- 금액을 답함: 그 금액의 원문이 제공되었는지 확인합니다. 자신 있는 문장이나 URL처럼 생긴 문자열만으로 사실이라고 판단하지 않습니다.

**“전문가처럼 답해”라는 지침은 없는 문서를 만들어 주지 않습니다.** 다음 실습에서 실제 회사 역할을 하는 가상 문서를 제공합니다.

## 5. 같은 모델을 코드에서 불러보기

준비된 가상 환경의 터미널에서 실행합니다.

```bash
python lab.py model "출장 준비 체크리스트를 한국어 3줄로 써 주세요."
```

실제 답변과 `outputs/model-...json` 경로가 출력됩니다. 파일에는 응답 ID와 사용량이 있습니다.

이 명령의 핵심은 다음 세 줄입니다. **읽기만 하면 됩니다. 별도 파일에 다시 작성하지 않습니다.**

```python
project = AIProjectClient(endpoint=project_endpoint, credential=credential)
client = project.get_openai_client()
response = client.responses.create(model=deployment_name, input=question)
```

실제 실행 코드에는 인증, 출력 한도, 오류 처리도 있습니다. [workshop.py](../workshop.py)의 `ask_model`에서 확인할 수 있습니다.

**브라우저와 코드가 서로 다른 AI를 부른 것이 아닙니다.** 같은 배포를 다른 사용 방식으로 호출한 것입니다. 코드 호출부터 모든 기능을 처음 작성해야 하는 것도 아닙니다.

## 6. 세 가지 변경을 구분하기

| 변경 | 무엇이 달라지나? | 모델 가중치가 바뀌나? |
|---|---|---|
| 프롬프트 수정 | 모델에게 주는 업무 지침 | 아니요 |
| 문서 검색 연결 | 답변 때 참고할 정보 | 아니요 |
| 파인튜닝 | 학습 데이터로 모델 자체를 조정 | 예. 이번 실습에서는 하지 않음 |

## 막히면

모델이 회사 규정을 이미 안다는 듯 답하면 원문을 요구하고 **근거 미확인**으로 기록합니다. 이 단계에서 일부러 더 위험한 질문을 만들거나 실제 회사 정보를 넣을 필요는 없습니다.

**핵심 한 문장:** 프롬프트는 행동을 정하고, 근거 데이터는 답할 수 있는 범위를 넓힙니다.
