# 강사 가이드 — v1.5를 7시간 안에 진행하기

**목표는 기능을 많이 소개하는 것이 아니라, 참가자가 하나의 도우미의 근거·실행·품질을 설명하게 하는 것입니다.**

기본 진행 방식은 **짧은 설명 → 참가자 실행 → 기대 결과와 대조 → 기록**입니다. 한 개념을 10분 이상 강의하기보다 화면에서 바로 확인합니다. 코드 작성 능력은 전제하지 않지만, 준비된 명령과 파일을 다룰 수 있는 PC 환경은 필요합니다.

## 1. 수업 운영 원칙

- 경로는 하나입니다. 포털반/코드반, A/B/C, 선택 심화 실습을 본 수업 중에 나누지 않습니다.
- 모든 참가자가 같은 가상 회사·문서·질문·배포 별칭을 사용합니다.
- 환경 설치·권한 승인·judge 연결·trace 연결은 사전에 끝냅니다.
- 최신 모델 소개, 멀티 에이전트, IQ, MCP, Hosted 배포는 본 수업 시간을 침범하지 않습니다.
- 오답도 성과입니다. 단, 실제 실행 결과와 개선 이유가 남아야 합니다.
- 준비된 해설·녹화·짝의 결과는 **본인의 Azure 실행 증거가 아닙니다**.

## 3. D-7: 범위와 비용 결정

| 준비 | 결정할 사항 |
|---|---|
| 대상 | Foundry 입문자, Python 작성 불필요. 파일 편집·명령 복사 가능 여부 확인 |
| 좌석 | 개인 PC/프로젝트 또는 사전에 합의한 짝 실습 |
| 권한 | 참가자용 데이터 작업 권한, 운영자용 관리·역할 할당 권한 분리 |
| 네트워크 | 포털·Azure CLI·프로젝트 Endpoint 접근, 조직 프록시/Private Link |
| 모델 | Responses·File Search·함수 호출을 함께 검증한 배포 |
| 평가 | Dataset 평가용 Azure OpenAI 연결과 지원 judge 모델 |
| 추적 | Application Insights 연결과 참가자의 조회 권한 |
| 비용 | 비용 책임자, 1인 허용 예산, 전체 예산, 허용 호출 수 |
| 종료 | 공유/개인 자원 목록과 삭제/보관 담당자 |

모델 가용성은 리전·배포 유형·할당량에 따라 달라집니다. 특정 모델이나 리전이 모든 구독에서 작동한다고 공지하지 않습니다. 예산 알림은 사용을 자동으로 차단하지 않으므로 운영자가 호출 수와 사용량을 같이 관리합니다.

v1.5는 **v1.2 기능 유지 + 학습 동선 개선**입니다. 전체 기능은 [대응표](feature-map.md)와 [상세 카드](features/README.md)에 있습니다. 상세 실습을 추가 운영한다면 해당 카드의 격리 SDK·데이터·리소스와 추가 시간을 사전에 준비합니다. 모든 고급 기능을 420분 안에 몰아넣거나, 기본 동선만 실행하고 모든 기능을 실습했다고 표현하지 않습니다.

**배포 자료에서 제외:** `.env`, `.lab/`, `outputs/`, `.venv/`, `.reference/`의 개인 설정·결과·가상 환경, 캐시 파일. 호환 소스는 준비 스크립트로 동일 커밋을 받게 합니다. 참가자에게 강사의 인증정보나 상태 파일을 복사해 주지 않습니다.

## 4. D-1: 강사 계정으로 전체 경로 실행

아래는 참가자에게 “환경 준비됨”이라고 말하기 위한 **실제 사전 점검**입니다. 가이드 작성 시 수행한 로컬 검사와는 별개입니다.

1. [준비 가이드](00-setup.md)의 새 개인 환경을 준비합니다. 별도의 고유한 강사 agent 이름을 사용합니다.
2. `python lab.py doctor`와 `python lab.py doctor --live`를 실행합니다.
3. `python lab.py create --stage rag` 후 현행 서울 질문을 실행합니다.
4. 세 파일 인덱싱, 실제 `file_search_call`, 현행 파일 인용을 확인합니다.
5. `python lab.py create --stage tools` 후 서울 2박 3일 질문을 실행합니다.
6. 함수 인수 서울/2, 반환값 390,000원, 답변과 인용을 확인합니다.
7. baseline 6문항 → 사람 검토 → improved 6문항 → 사람 검토를 수행합니다.
8. 앱에서 실제 응답을 받습니다. UI만 열리는 것으로 대체하지 않습니다.
9. 생성된 실제 응답 파일로 **Dataset / Individual turns / Relevance** 평가를 완료합니다.
10. 자신의 실제 응답 ID와 연결되는 **Foundry trace**를 엽니다.
11. holdout 4문항을 수행하고 검토합니다.
12. 삭제 대상을 조회한 뒤 강사 자신의 자산만 정리합니다. 포털 자산과 비용 자원도 별도 확인합니다.

**수업 시작 허용 기준**

- [ ] 모델 호출, 파일 검색, 실제 함수 호출이 모두 확인됨.
- [ ] 포털 Dataset 평가가 행 누락 없이 Completed.
- [ ] 참가자와 같은 권한으로 trace를 열 수 있음.
- [ ] 강사의 실제 실패 사례 1건과 해결 과정을 설명할 수 있음. 실패가 없으면 억지로 만들지 않음.
- [ ] 초보자가 같은 명령을 따라갈 수 있는지 최소 1명에게 진행을 확인받음.
- [ ] 모델명/버전/배포 유형/리전과 SDK 고정 버전을 준비 카드에 기록함.
- [ ] 클라우드 작업의 실제 소요 시간을 확인하고 수업 시간표를 점검함.

File Search가 작동하지 않으면 인라인 문서로 바꿔 놓고 RAG 성공이라고 하지 않습니다. 지원 모델·권한·저장소를 해결하거나 수업 범위 변경을 명시합니다. native 평가/trace가 안 되면 해당 학습 목표를 완료했다고 안내하지 않습니다.

## 5. 핵심 설명 문장과 흔한 오해

| Lab | 이 한 문장을 남기기 | 바로잡을 오해 |
|---|---|---|
| 01 | Foundry는 업무용 AI의 개발·운영 플랫폼이다 | Foundry = GPT |

| 07 | 학습 완료와 생산 운영 승인은 다르다 | localhost 앱 = 운영 배포 |

## 6. 진행 중 시간을 지키는 방법

**3분 막힘 규칙:** 같은 오류에 3분 이상 멈추면 오류 종류·마지막 성공 단계·현재 버전을 적고 운영 지원을 받습니다. 앞 실습을 처음부터 반복하지 않습니다.

| 상황 | 할 일 | 하지 않을 일 |
|---|---|---|
| 일부 계정 권한 문제 | 참가자 계정/프로젝트와 담당자 권한 확인 | 강사 토큰이나 비밀번호 공유 |
| 429가 반복됨 | 동시 호출을 나눠 진행, 지원 배포·할당량 확인 | 모든 참가자에게 계속 재실행 지시 |
| 평가가 느림 | 6행·한 evaluator 확인, 기다리는 동안 trace 진행 | judge를 여러 개 추가 |
| 모델이 이미 좋은 답을 냄 | 개선 없음도 정상으로 기록 | 일부러 실패 점수를 입력 |
| 특정 화면에 메뉴가 없음 | 현재 프로젝트·새 포털 확인, 공식 문서 대조 | 옛 스크린샷과 픽셀 위치를 강제 |
| 한 사람이 끝까지 막힘 | 동의한 짝 환경에서 실행/관찰을 구분해 기록 | 짝 결과를 개인 결과로 제출 |

시간이 부족하면 추가 질문·코드 깊이 읽기·전체 발표를 줄입니다. **실제 근거 확인, 전후 평가, 권한 경계, 자원 정리는 빼지 않습니다.** 필수 단계가 남았다면 미완료와 보충 시간을 명시합니다.

## 7. 수업 후 평가와 인계

산출물은 “화면 캡처 개수”가 아니라 다음 다섯 가지입니다.

| 산출물 | 볼 것 |
|---|---|
| 개념 설명 | Foundry·모델·프로젝트·에이전트·도구를 구분 |
| 실제 응답 | 근거 파일과 계산 결과를 대조 |
| 평가 기록 | dev 전후·holdout·실패 이유·선택 버전 |
| 운영 기록 | 앱·포털 평가·본인 trace·비용 항목 |
| 적용/정리 카드 | 사용할 데이터/도구/승인 경계/담당자 |

개인 실행 기록에는 질문·답변이 있으므로 공개 저장소로 일괄 수집하지 않습니다. 피드백은 완료/미완료 단계, 막힌 시간, 어려운 용어처럼 필요한 정보만 모읍니다.

**강사용 안내는 여기까지입니다. 참가자는 [Lab 01](01-foundry.md)부터 한 경로로 진행합니다.**
