# 자가 실습 체크포인트

이 문서는 혼자 진행하는 참가자와 진행을 돕는 사람 모두를 위한 점검표입니다. **별도 강사가 환경을 제공해야 하는 과정이 아닙니다.**

## 시작

- 본인의 Entra 계정과 활성 구독 Owner 확인.
- PC의 개발 도구 설치 권한과 승인된 네트워크 확인.
- 실습 전용 그룹·모델·데이터 역할 직접 생성/확인.
- 하나의 prefix, Python 환경, 한빛기술 데이터 세트로 통일.
- 예상 비용과 중단 시 정리 절차 확인.

## 구간별 확인

| 구간 | 다음으로 넘어갈 근거 |
|---|---|
| 00~02 | 내 프로젝트/모델의 실제 응답, 설정 출처 |
| 03~05 | 관리형 agent, 실제 파일/함수/MCP, 워크플로/모의 승인 구분 |
| 06~07 | 스스로 만든 Search·모델·역할, 전체 dev와 native 평가 |
| 08~09 | 실제 Hosted 버전·런타임 ID·trace |
| 10~11 | 도구 공유/Skill·Memory·A2A·예약의 실제 결과와 정리 |
| 12~13 | 고정 평가 조건·후보 검토·적용된 통제 |
| 14 | 추가 권한 여부와 실행/설계 상태 |
| 15 | 선택 대상의 인수와 모든 비용 자원의 정리/보관 |

오류나 미지원 기능 때문에 다른 모델·provider·fixture를 몰래 선택하지 않습니다. 독립적인 다음 학습을 이어갈 수는 있지만 막힌 기능은 **미완료**로 남깁니다.

## 도움을 줄 때

정답을 대신 입력하기보다 실패 지점·실제 identity·원문·기록을 같이 봅니다. 다른 사람의 성공 결과, 토큰, 강사 계정을 나누어 주지 않습니다.

교육 목적으로 그룹을 운영하더라도 먼저 참가자 스스로 00의 준비 절차를 수행할 수 있는지 확인합니다. 시간표 대신 단계별 완료 조건으로 진행합니다.

## GitHub 계정 없이 파일 배포

자료 소유자는 다음 명령으로 참가자용 ZIP을 만듭니다.

```bash
python scripts/package_workshop.py
```

`dist/microsoft-foundry-v1.5-selfstudy.zip`에는 가이드·실행 도구·합성 예제와 hash manifest만 포함됩니다. `.env`, `.selfstudy`, `.reference`, 가상 환경, 실행 결과, Git 이력은 제외합니다.

압축을 푼 참가자는 00의 공개 고정 소스 다운로드부터 시작합니다. ZIP에 로컬 인증정보나 강사의 Azure 설정을 추가하지 않습니다. 이미 같은 ZIP 이름이 있으면 덮어쓰지 말고 `--output dist/새이름.zip`으로 새 판을 만듭니다.
