# Lab 01. Foundry 이해와 첫 성공

**35분 · 브라우저 · 목표: Foundry를 한 문장으로 설명하고, 내 프로젝트에서 첫 답변을 받습니다.**

준비물: [수업 전 준비](00-setup.md)를 마친 프로젝트와 `workshop-chat` 배포.

| 시간 | 할 일 |
|---|---|
| 5분 | 완성할 도우미와 업무 문제 확인 |
| 5분 | Foundry의 역할 이해 |
| 10분 | 내 모델로 첫 질문 |
| 10분 | 프로젝트·모델·배포·에이전트 구분 |
| 5분 | 설명하고 기록 |

## 1. 우리가 해결할 문제

직원이 출장 갈 때마다 담당자에게 같은 질문을 합니다.

> “서울 숙박비는 얼마까지죠? 이번 2박 3일은 얼마죠? 어떤 규정인가요?”

그냥 챗봇을 붙이면 답은 빨리 나올 수 있습니다. 그러나 **틀린 규정, 틀린 계산, 승인한 것처럼 보이는 답변**은 오히려 일을 늘립니다.

오늘의 성공 기준은 질문에 잘 대답하는 것에서 끝나지 않습니다. **답변의 근거와 실행 과정을 확인하고, 바꾼 뒤 품질을 비교하는 것**까지입니다.

## 2. Foundry를 이렇게 이해하세요

```text
모델        : 문장을 이해하고 답변을 만드는 엔진
에이전트    : 그 모델에 업무 지침과 쓸 수 있는 도구를 연결한 도우미
Foundry     : 모델·에이전트·지식·평가·운영을 함께 다루는 Azure 플랫폼
프로젝트    : 내가 만드는 에이전트와 관련 작업을 묶는 작업 공간
```

플랫폼이 있으므로 모델만 호출할 때 직접 흩어져 관리하던 **에이전트 버전, 파일 검색, 평가, 추적, 접근 권한**을 연결해 볼 수 있습니다. 그렇다고 회사 규정의 정확성이나 업무 승인 책임까지 자동으로 해결되지는 않습니다.

| 비교 대상 | 가장 짧은 구분 |
|---|---|
| Azure OpenAI 모델 사용 | OpenAI 모델을 Azure에서 호출하는 기능. Foundry는 모델 외에 에이전트 개발·운영까지 다룸 |
| Microsoft 365 Copilot | 이미 제공되는 업무용 AI 경험. 여기서는 우리 용도의 AI를 직접 만듦 |
| Copilot Studio | 로우코드 중심의 에이전트 제작·연결. 필요 역량과 통합 대상에 따라 선택 |
| Microsoft Agent Framework | 코드에서 에이전트·워크플로를 작성하는 프레임워크. Foundry라는 플랫폼 자체와는 다름 |

서로를 전부 대체하는 제품 목록이 아닙니다. **내가 무엇을 직접 만들고 운영할 것인지**가 선택 기준입니다.

## 3. 10분 안에 첫 답변 받기

1. [Foundry 포털](https://ai.azure.com)을 엽니다.
2. 왼쪽 위에서 **내 프로젝트**를 선택합니다. 담당자와 같은 화면인지 이름부터 대조합니다.
3. **Build → Models** 또는 모델 배포 목록에서 `workshop-chat`을 찾습니다.
4. 배포를 열고 **Playground**로 이동합니다.
5. 다음 질문을 전송합니다.

```text
처음 국내 출장을 가는 직원을 위한 준비 체크리스트를 한국어 3줄로 써 주세요.
```

**기대 결과:** 출장 목적, 일정, 준비물 같은 일반적인 체크리스트가 나옵니다. 문장이 예시와 똑같을 필요는 없습니다.

**아직 확인하지 않은 것:** 이 답변이 다온테크의 실제 규정에 맞는지, 문서를 검색했는지, 승인 시스템에 연결했는지. 지금은 일반 모델을 한 번 호출했을 뿐입니다.

## 4. 네 가지 이름을 내 화면에서 찾아보기

| 이름 | 예시 | 확인할 곳 |
|---|---|---|
| 프로젝트 | `foundry-lab-01` | 프로젝트 선택 영역 |
| 모델 | `gpt-4.1-mini` | 배포 상세의 기반 모델 |
| 배포 이름 | `workshop-chat` | 모델 배포 목록 |
| 에이전트 | `trip-coach-01` | 아직 없음. Lab 03에서 생성 |

모델은 **차종**, 배포 이름은 내 서비스가 호출할 **등록 이름** 정도로 생각하면 됩니다. 실제 API에는 준비된 배포 이름을 넣습니다.

Foundry 리소스는 이 프로젝트를 담는 상위 Azure 리소스입니다. 구독은 과금·관리 경계이고, 리소스 그룹은 수업 자원을 묶어 관리하는 상자입니다. 이 용어를 모두 외우기보다 **내가 지금 어느 프로젝트에서 비용을 쓰고 있는지**부터 분명히 하세요.

## 5. 저장할 것

[워크북](../worksheets/workbook.md)의 Lab 01에 다음을 기록합니다.

- 내 프로젝트, 모델명, 배포 이름.
- 실제로 받은 첫 답변 한 줄.
- “Foundry는 ______이고, 단순 모델 호출과 다른 이유는 ______이다.”

짝에게 설명해 보세요. **“Foundry는 GPT 모델이다”**라고 설명했다면 2절을 다시 확인합니다.

## 막히면

모델이 없으면 새 모델을 임의로 배포하지 말고 담당자에게 `workshop-chat` 배포를 확인받습니다. 답변이 없거나 권한 오류가 나면 [프로젝트·권한 문제](troubleshooting.md)를 해결합니다.

**핵심 한 문장:** Foundry는 모델을 고르는 곳에서 끝나지 않고, 업무용 AI를 만들고 관리하는 플랫폼입니다.
