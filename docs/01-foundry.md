# 01. Foundry와 첫 모델 응답

**완료 목표:** Foundry를 설명하고, 설정한 **GPT-6 Sol**에서 실제 응답을 받습니다.

**시작 조건:** [00](00-setup.md)의 프로젝트·Sol 배포·권한·설정. 이 장에서는 다른 모델이나 새 자원을 추가하지 않습니다.

## 무엇을 왜 배우는가

직원이 “출장 호텔을 예약해도 되는가?”라고 묻습니다. 빠른 답변만으로는 부족합니다. 적용 날짜와 규정을 구분하고, 근거를 제시하며, 실제 승인 권한이 없다는 경계를 지켜야 합니다.

| 말 | 이 과정의 뜻 |
|---|---|
| 모델 | 문장을 이해하고 생성하는 엔진 |
| 배포 이름 | 내 코드가 모델을 호출하는 별칭. 새 환경은 Sol의 `workshop-chat` |
| 에이전트 | 모델에 업무 지침과 사용할 도구를 연결한 도우미 |
| 프로젝트 | 에이전트·평가·연결·파일 작업을 묶는 공간 |
| Foundry | 모델·에이전트·지식·도구·평가·운영을 함께 다루는 플랫폼 |

Azure OpenAI 모델 호출은 Foundry의 기능 중 하나이고, **Microsoft Agent Framework(MAF)는 코드를 구성하는 프레임워크**입니다. 코드 프레임워크와 관리형 플랫폼은 같은 객체가 아닙니다.

## 1. 포털에서 한 번

1. Foundry에서 내 프로젝트를 선택합니다.
2. **Build → Models / Deployments → 내 실제 Sol 배포 → Playground**를 엽니다. 새 환경은 `workshop-chat`; 이전 환경은 00에서 확인한 실제 Sol 별칭을 사용합니다.
3. 다음 질문을 보냅니다.

**Tools에 Web search가 기본 추가되어 있으면 제거**합니다. 이번에는 검색 없는 모델 호출만 확인합니다. 새 탭이나 대화에서도 불필요한 도구·추가 과금 설정을 다시 확인합니다.

```text
처음 국내 출장을 가는 직원의 준비 체크리스트를 한국어 3줄로 써 주세요.
```

일반적인 일정·목적·준비물 답변이 나오면 첫 모델 호출 성공입니다. **아직 한빛기술 규정을 검색하거나 도구를 실행한 것은 아닙니다.**

## 2. 같은 Sol 배포를 코드에서

README가 있는 실습 폴더에서 실행합니다. 설정한 실제 Sol 배포를 그대로 호출합니다.

```bash
python scripts/workshop.py model --question "처음 국내 출장을 가는 직원의 준비 체크리스트를 한국어 3줄로 써 주세요." --output outputs/learner-notes-ko/01-sol-model.json
```

실제 답변, 기반 모델/배포 정보, 응답 ID와 사용량을 읽습니다. 빈 응답이나 오류는 성공이 아닙니다. 같은 질문의 문장이 매번 같을 필요는 없습니다.

핵심은 `AIProjectClient → get_openai_client → responses.create`입니다. 모델 별칭만 보지 말고 실제 **gpt-6-sol / 2026-09-22**와 연결되었는지 확인합니다. 기존 파일이 있다면 덮어쓰지 않고 새 출력 이름을 선택합니다.

### 프로젝트 API와 계정 API를 구분하기

이번 기본 호출은 **`project-responses`**입니다. 02에서 선택적으로 Luna와 비교할 때만 두 모델 모두 같은 명시적 **`account-responses`**를 사용합니다. API 성공을 서로 대신하거나 오류 후 자동 전환하지 않습니다.

이전 환경의 Sol이 `workshop-compare`로 배포되어 있어도 이름을 바꾸거나 새 기본 이름의 모델을 교체하지 않습니다. [00의 명시적 설정](00-setup.md#8-실제-값으로-설정-자동-수집)과 [모델 별칭 안내](model-selection.md#기존-배포를-그대로-재사용하기)를 따릅니다.

## 3. 세 가지 구현을 구분

| 구현 | 정의/실행 위치 | 이후 실습 |
|---|---|---|
| Prompt Agent | Foundry에 지침·도구·정확한 버전을 저장 | 03 |
| 로컬 MAF/워크플로 | 내 Python이 작업을 구성하고 Azure 모델을 호출 | 04~05 |
| Hosted Agent | 내 코드를 Foundry 런타임에 배포 | 08 |

같은 합성 업무를 다루지만 서로 다른 실행입니다. 로컬 결과로 원격 배포 성공을 대신하지 않습니다.

## 기록과 확인

프로젝트, 실제 기반 모델/버전, 배포 별칭, API, 응답 ID와 새 결과 파일을 워크북에 기록합니다.

**스스로 설명:** “Foundry는 ______이고, 모델 호출 외에 ______를 함께 다룬다.”

401/403은 로그인 주체·테넌트·데이터 역할, 404는 프로젝트 Endpoint와 실제 배포 이름, 429는 할당량을 먼저 확인합니다. [문제 해결](troubleshooting.md).
