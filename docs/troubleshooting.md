# 막혔을 때 — 다시 만들기 전에 확인하기

**오류 메시지, 마지막 성공 단계, 선택 버전을 먼저 남깁니다.** 인증정보를 스크린샷이나 질문에 포함하지 않습니다.

## 첫 세 가지 확인

1. 터미널이 이 폴더이고, 준비한 `.venv`의 Python인가?
2. 브라우저와 CLI가 같은 계정·프로젝트를 사용하고 있는가?
3. `.env`와 `python lab.py status`의 대상이 같은가?

## 증상별 해결

| 증상 | 원인 후보 | 다음 행동 |
|---|---|---|
| `No module named ...` | 다른 Python, 패키지 미설치 | 가상 환경 활성화 후 `python -m pip install -r requirements.txt` |
| 패키지 버전 불일치 | 원본 v1.2나 다른 프로젝트의 환경 | 이 폴더의 `.venv`와 고정 requirements 사용 |
| `.env`를 바꿨는데 옛 값 사용 | 셸 환경변수가 우선 | 기존 export를 해제하거나 깨끗한 새 터미널에서 활성화 |
| Endpoint 오류 | 모델 URL/구독 ID 사용, 예시 값 미치환 | 포털의 프로젝트 Endpoint를 다시 복사 |
| 401 / 로그인 필요 | CLI 로그인 만료·잘못된 테넌트 | 정상 `az login` 후 올바른 구독 선택 |
| 403 / Forbidden | 데이터 작업 권한, Storage 권한, 네트워크 | 담당자와 필요한 범위의 역할·연결 확인. 무조건 Owner 부여 금지 |
| Public access disabled / 연결 시간 초과 | Private Endpoint·방화벽·프록시 | 승인된 네트워크 경로 확인. 공개 접근을 임의로 켜지 않음 |
| Deployment not found / 404 | 모델명과 배포 별칭 혼동 | `FOUNDRY_MODEL_DEPLOYMENT_NAME`과 실제 배포 이름 대조 |
| 같은 agent 이름이 이미 있음 | 다른 실습 또는 사람의 에이전트 | 기존 자산을 수정하지 않고 고유한 이름 사용 |
| `.env와 기존 실습 상태가 다름` | 실행 도중 프로젝트·이름 변경 | 원래 설정으로 복원. `.lab` 삭제로 회피하지 않음 |
| `상태 파일의 형식 오류` | 상태 파일 편집·다른 버전 혼합 | 파일을 보관하고 담당자 확인. 임의로 ID 수정 금지 |
| `다른 실습 작업이 실행 중` | 동일 폴더의 CLI/앱 요청 중복 | 먼저 실행한 작업이 끝날 때까지 기다림. 정상 완료 시 잠금 자동 해제 |
| 429 / quota 초과 | 공유 배포 동시 호출·한도 | 기다린 후 소규모 재시도, 운영자가 배포/할당량 확인 |
| 인덱싱 `in_progress` | 업로드 후 처리 중 | 잠시 기다려 재시도. 같은 파일을 포털로 중복 업로드하지 않음 |
| 인덱싱 `failed` / 도구 미지원 | 파일·스토리지·모델 지원 문제 | 원본 에러와 공식 File Search 요구사항 확인 |
| 다음 날 검색 실패 | 저장소가 마지막 활동 후 1일 만료 | 소유 자산 상태 확인 후 담당자와 새 실습 세션 준비 |
| 답은 있는데 파일 인용 없음 | 검색 생략·인용 미생성 | 저장한 버전의 File Search와 지침, 실제 `file_search_call` 확인 |
| 과거 금액을 현재에 적용 | 검색 결과를 날짜로 구분하지 않음 | 실제 실패를 기록하고 Lab 05의 날짜 규칙 개선 |
| 함수가 포털에서 실행되지 않음 | 로컬 Python 실행기가 없음 | 계산 질문은 `lab.py ask` 또는 앱에서 실행 |
| `tool_calls: []` | 도구 버전 미선택·모델이 호출하지 않음 | `status`의 stage 확인. 실제 로그가 없으면 도구 성공으로 처리하지 않음 |
| `invalid_tool_input` | 도시·숙박 수 형식/범위 오류 | 올바른 사용자 입력 확인. 오류를 0원 견적으로 바꾸지 않음 |
| 함수 호출 상한 도달 | 모델이 같은 도구 반복 요청 | 로그를 보고 지침/입력을 수정. 상한부터 무작정 늘리지 않음 |
| 응답 `incomplete` / 텍스트 없음 | 출력 한도·중단·refusal 등 | `responses[].output`와 상태 확인. reasoning 모델 대체 시 수업 전 재점검 |
| label 폴더가 이미 있음 | 기존 결과 보호 | 새 label 사용. 이전 기록을 지워 결과를 덮어쓰지 않음 |
| `review.csv` 채점 실패 | 빈 판정·빈 이유·다른 열 수정·응답 누락 | pass/reason만 편집, 원본 응답과 버전 확인 |
| CSV 한글 깨짐 | 편집기의 인코딩 해석 | UTF-8로 가져오기. 생성 CSV는 UTF-8 BOM 포함 |
| 앱이 빈 화면/설정 오류 | 준비·agent 생성 미완료 | Lab 00 및 03~04 완료 후 앱 재실행 |
| 앱에 표시된 버전과 이전 답변 버전이 다름 | 버전 선택 후 이전 답변이 화면에 남음 | 답변에 함께 표시된 실행 버전 확인. 새 질문으로 재확인 |
| 포트 8501 사용 중 | 다른 서버가 사용 중 | 기존 사용자를 건드리지 말고 `--server.port 8502` 등 다른 포트 사용 |
| trace 없음 | 연결·권한·수집 지연·프로젝트 혼동 | App Insights 연결, 조회 역할, 최근 시간 범위 확인 |
| judge 모델이 안 보임 | 평가용 Azure OpenAI 연결/지원 모델 미준비 | 담당자가 연결과 지원 배포 준비. 평가를 생략한 채 완료로 처리하지 않음 |
| 포털 평가 `Partial` / `Failed` | 매핑·quota·필수 입력 | 오류 행 확인. Dataset, query/response, Relevance 하나인지 재확인 |
| 삭제 실패 | 소유 범위·권한·네트워크 | 남은 상태를 보존하고 해결 후 동일 cleanup 재실행 |

## 다시 시작할 때

**실습 도중:** 원래 폴더, `.env`, `.lab/state.json`을 유지합니다. `status`로 마지막 버전을 확인하고 해당 Lab의 다음 단계부터 진행합니다.

**완전히 새 회차:** 기존 개인 자산을 정리하고 결과를 보관한 뒤 **별도 실습 폴더와 고유한 agent 이름**을 사용합니다. 공유 폴더를 초기화하거나 다른 참가자 상태를 복사하지 않습니다.

**비정상 종료로 잠금만 남은 경우:** `.lab/session.lock`에는 실행 프로세스 ID가 있습니다. 담당자가 해당 프로세스와 이 폴더의 실습 작업이 모두 종료되었음을 확인한 뒤 **그 잠금 파일 하나만** 제거합니다. 실행 중인 작업의 잠금을 지우거나 `.lab` 전체를 삭제하지 않습니다.

```text

현재 프로젝트 이름과 agent 버전:

오류 종류와 메시지:
응답 ID 또는 오류 기록 파일:
이미 확인한 것:
```

API key, 토큰, 비밀번호, 실제 회사 문서 원문은 넣지 않습니다. **오류가 해결되지 않았으면 미완료라고 기록하는 것이 올바른 결과입니다.**
